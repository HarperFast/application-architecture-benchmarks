# Contributing

Follow Harper's [organization contribution guidelines](https://github.com/HarperFast/.github/blob/main/CONTRIBUTING.md) and [Code of Conduct](https://github.com/HarperFast/.github/blob/main/CODE_OF_CONDUCT.md).

Read [README.md](README.md) first. Contributions must follow its application specification, measurement rules, implementation guidance, and claim rules. [Reporting results](README.md#reporting-results) explains how to submit an implementation or challenge a result.

## Especially welcome

Maintainers and users of the measured technologies: tell us about misconfiguration, outdated guidance, or missed performance improvements. Pull requests improving competing implementations are especially useful.

## Before you start

Open an issue or join [Discord](https://harper.fast/discord) before large changes, especially a new stack whose scope and conformance need agreement.

Specification, dataset, and measurement-rule changes affect every result produced under them. Expect more discussion and slower merges than for changes to one implementation.

## After a merge

Merged changes enter the next comparison run; benchmarks are not re-run for every pull request. Published results remain dated snapshots. If a change invalidates one, use the challenge process rather than editing the snapshot.
